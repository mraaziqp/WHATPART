# WHATPART

South Africa's marketplace for vehicle parts: vehicle fitment, multi-seller offers, instant search and PayFast checkout.

Live: https://whatpart.africa

## Stack

- **App**: Next.js 16 (App Router, server-rendered for SEO), React 19, TypeScript, Tailwind CSS v4
- **Database**: PostgreSQL 17 via Prisma 7 (`prisma/schema.prisma`)
- **Search**: Meilisearch (typo-tolerant, faceted; `src/lib/search.ts`)
- **Auth**: better-auth, email + password (`src/lib/auth.ts`)
- **Payments**: PayFast hosted checkout + ITN webhook (`src/lib/payfast.ts`, `src/app/api/payfast/itn`)
- **Hosting**: Contabo VPS, Docker Compose at `/opt/whatpart`, Caddy (in the n8n stack at `/opt/n8n`) for HTTPS

## Data model in one paragraph

A **Product** is a catalogue part (brand, category, specs, images). Sellers list it through **Offers**
(condition, price, stock, warranty, dispatch time), so one product page compares every seller, like
Takealot or Amazon. **Fitments** link products to **Vehicles** (model + engine + year range); the
shopper's selected vehicle (cookie `wp_vehicle`) filters search and drives the "fits / doesn't fit" checks.
**Deals** are time-boxed offer prices. Orders snapshot titles and prices at purchase. Money is integer cents.

## Marketplace operations

- **Sellers** apply at `/sell/apply`, then manage everything at `/seller`: list parts from the catalogue
  (search first, so every seller competes on one product page), add new parts with photos and fitment,
  update price and stock, confirm and ship orders, and quote on part requests. Buyers' street addresses are
  only shown to sellers once an order is paid.
- **Admins** work at `/admin` (404 for everyone else): approve or suspend sellers, mark orders paid with a
  payment reference, cancel orders, mark deliveries, and forward part-request quotes to buyers.
  Make someone an admin after they register:
  `cd /opt/whatpart && docker compose run --rm tools npx tsx scripts/make-admin.ts their@email.com`
- **Payments**: until a gateway is approved, checkout takes orders as *awaiting payment* and the team sends
  a payment link, then marks the order paid in `/admin`. `PAYMENT_GATEWAY=payfast` in `app.env` switches
  checkout to PayFast's hosted page (with merchant credentials set).
- **Photos** are re-encoded to WebP (EXIF/GPS stripped) and stored in `/opt/whatpart/data/uploads`.
- **Deals** are scheduled in `/admin/deals` (times are SAST). Search entries record when their deal ends,
  so an expired deal is never advertised even before the index is refreshed.
- **Customers** get My Garage (vehicles saved automatically, VIN lookup), a wishlist, reviews limited to
  verified buyers, and guest order tracking at `/track` (order number + email).

## Server operations

`ops/` holds the server config: the production `docker-compose.yml` (with log rotation) and
`backup.sh` (database dump + photos, 14 days kept in `/opt/whatpart/backups`). Deploys install both.
Scheduled jobs are opt-in: `./deploy.sh install-schedule` installs `ops/whatpart.cron` (nightly backup,
nightly search rebuild, 15-minute deal refresh); `./deploy.sh remove-schedule` removes them.
Run a backup by hand with `./deploy.sh backup`.

Security: per-request nonce Content-Security-Policy (`src/proxy.ts`), roles checked in the database on
every admin/seller request, rate-limited sign-in, and buyers' addresses hidden from sellers until paid.

## Local development

The local app talks to the VPS database and search through an SSH tunnel:

```bash
npm install
npm run tunnel          # keep running: forwards VPS Postgres -> :15432, Meilisearch -> :17700
npm run dev             # http://localhost:3000
```

`.env` (gitignored) holds `DATABASE_URL`, `MEILI_HOST`, `MEILI_MASTER_KEY`, `BETTER_AUTH_SECRET`; see `.env.example`.

| Task | Command |
|---|---|
| Change the schema | edit `prisma/schema.prisma`, then `npm run db:migrate -- --name <change>` |
| Reseed demo catalogue | `npm run db:seed` then `npm run search:reindex` (refuses once real sellers exist) |
| Type-check and lint | `npm run lint` |

## Deploying

```bash
./deploy.sh            # upload, build image on the VPS, run migrations, restart, health-check
./deploy.sh rollback   # back to the previously deployed image
./deploy.sh reindex    # rebuild the search index from the database
```

Production settings live in `/opt/whatpart/app.env` on the VPS (not in git):
`SHOW_DEMO_SELLERS` (hide seeded demo stock with `false`), `PAYMENT_GATEWAY` and the `PAYFAST_*` merchant credentials.

## Demo data

The catalogue is generated by `prisma/seed.ts`: ~1,000 parts for 33 popular South African vehicles from
8 demo sellers (all flagged `isDemo`). Part numbers are WHATPART catalogue numbers (`WP-…`), not
manufacturer numbers, and fitment is illustrative. Replace with real seller stock before taking real orders.
